Project summary

An assistant designed around what the evidence can support.

Nora is an exploration of trustworthy assistant behavior. Instead of treating retrieval as a hidden preprocessing step and the language model as the product, the workflow exposes a sequence of responsibilities: understand the request, retrieve relevant material, evaluate whether it is sufficient, construct a grounded response, refuse when support is inadequate, and route ambiguous or consequential cases for human review.

The project connects AI architecture with program-governance questions. Who owns the source material? What happens when two sources conflict? When should the system stop? Which events should be logged for review? Those choices determine whether an assistant is merely impressive in a demo or dependable in a real workflow.

Challenge

Useful answers and honest boundaries must coexist.

Retrieval-augmented generation can reduce unsupported output, but retrieval alone does not guarantee grounding. A system may retrieve weak evidence, ignore a contradiction, cite a source that does not support its claim, or answer a question outside the available corpus.

The design problem was to make evidence sufficiency an explicit decision. Nora needed to distinguish between a confident grounded answer, an answer that should carry caveats, a request that required clarification, and a request that should be refused or escalated.

Constraints

Quality is a pipeline property.

  • Retrieval quality: Relevant-looking text may still fail to answer the user's actual question.
  • Conflicting evidence: Multiple sources can differ in date, authority, or interpretation.
  • Traceability: A reviewer needs to understand why the assistant responded, refused, or escalated.
  • User experience: Boundaries must be communicated clearly without turning every answer into legalistic boilerplate.
  • Human attention: Review routing should reserve people for cases where judgment adds real value.

What I built

A governed response path.

I structured Nora as a stateful workflow rather than a single prompt. The architecture separates retrieval, evidence assessment, response generation, validation, refusal, and human-review routing. This makes the failure modes easier to locate and creates places where policies, thresholds, and logging can be introduced.

I also designed the interface around source visibility. A user should be able to connect an answer to its supporting material, while the system should communicate when available sources are incomplete. The refusal path is not a dead end: it can explain what is missing, invite a narrower question, or send the case to an appropriate reviewer.

A refusal is good product behavior when it preserves the user's ability to make a sound decision.

Outcome

A public architecture for inspectable AI behavior.

Nora demonstrates the components of an evidence-aware assistant and the governance logic around them. The repository makes the approach available for review, while the workflow and interface images show how the system separates answer generation from evidence evaluation.

The value of the project is not a claim that hallucination has been eliminated. It is a concrete design for making unsupported output less likely, more detectable, and easier to route for correction.

Methods

Architecture and governance approach.

  • Retrieval-augmented generation with explicit evidence context.
  • LangGraph-style state transitions and conditional routing.
  • Response validation against available sources.
  • Refusal and clarification paths for insufficient evidence.
  • Human-review routing for ambiguous or consequential cases.
  • Provenance, logging, and review-oriented interface decisions.
  • Development support using Claude Code and Codex.

Reflection

What I would test next.

I would create a formal evaluation set covering answerable, partially answerable, conflicting, ambiguous, and out-of-scope requests. Each route should have measurable expectations for grounding, citation support, refusal quality, and escalation. I would also test whether users notice and correctly interpret evidence limitations rather than assuming any citation guarantees correctness.

The project reinforced a program-management view of AI: model behavior, source ownership, policy, interface, and human operations must be designed together.
